# U2 action/evidence contract

RepositoryActions owns the reviewed file list and fixed command plans. Process is the platform adapter; Mission/ProgressStore remain platform-independent and unchanged. main.cpp translates menu commands; it contains no shell. Mission metadata cannot grant new capabilities. The public process adapter is infrastructure, not exposed as an arbitrary-command UI.

Build action compiles exactly Mission.cpp, ProgressStore.cpp and engine_tests.cpp with the university/include path and fixed C++20 options. It creates a new output directory, and executes the freshly built engine test only after compiler success. No stale binary fallback exists. The launcher separately compiles the U2 adapter/tests and the console; U2 tests do not recursively invoke themselves. Executable staging never replaces a running executable.

Evidence schema 1 is a single JSON object: origin=machine_observed, action, repository, recorded_unix_ms, passed, intentional_failure_probe, error, output_encoding, commands[]. Each command has executable, argv[], cwd, started, exit_status, handed_off, timed_out, output_limited, elapsed_ms, error and output. Combined stdout/stderr uses one pipe. Byte values are escaped into U+0000..U+00FF to preserve non-UTF8 Windows compiler bytes; decode JSON output with Latin-1 to recover original bytes. Raw output-N.txt is authoritative. Paths/argv are UTF-8 byte strings under the same escape mapping. Display escapes terminal control bytes; stored bytes are unchanged. No AI evaluation is involved.

started means a child process was created (on POSIX, exec failure returns 127). exit_status=-1 means unavailable/unobserved except Visual Studio handoff, which uses null and handed_off=true. Overall pass requires every planned command executed successfully and no action/save error. Actions stopped by missing tools have an error and zero commands when nothing ran. A deliberate failure is never converted to a normal pass. Evidence cannot mark U1 mastered, add a Git commit or mutate course definitions.

Each action reserves a unique directory, writes raw output and a staged evidence.json.tmp, closes it then renames to evidence.json. Final-file presence is the completion marker; no previous action is overwritten. This is local recoverability, not a power-loss durability or cryptographic attestation guarantee. Evidence refers to command/cwd/time, not an immutable source digest. Re-running after source changes creates a new record; retain the relevant Git diff yourself until a later reviewed provenance feature exists.

Git reads use fixed status/diff operations after root/config-key checks. Global/system configuration is deliberately excluded to avoid unrelated helper behavior; local configured filters are refused. There is no network operation, external diff, text conversion, pager, fsmonitor or optional index refresh. diff.autoRefreshIndex=false is additionally required: testing found that git diff refreshed the original stale file-stat cache without this setting. Staged object IDs/path entries were unchanged, and the review restored the exact submitted index before final verification. The regression fixture includes a clean file with changed mtime. Untracked contents are not included in diff. Read-only Git operations still create separate University evidence records outside .git.

Reference contracts used during implementation: [Git diff options](https://git-scm.com/docs/git-diff) for --no-ext-diff/--no-textconv and [Windows process redirection](https://learn.microsoft.com/en-us/windows/win32/procthread/creating-a-child-process-with-redirected-input-and-output) for process I/O. These documentation checks do not constitute Windows execution evidence.
